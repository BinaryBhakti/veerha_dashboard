17Workflows index /workflowsA2 · queue

Every completed run in the live log reads step 9 of 8, and the same workflow reports 8, 2 and 9-of-8 as its total. Progress is now stated once, from the workflow definition: a finished run says what it finished, a waiting run says what it is waiting for and when it resumes, and a stopped run says where it stopped. No fraction can exceed its denominator because the fraction is no longer the only thing shown. Waiting and Completed were the only two statuses the live app ever rendered — Needs you, Stopped and Failed are drawn here because a run log without them cannot be read.

36Deliveries & tools /deliveriesA1 · index

The one question this screen exists to answer — did this actually reach a customer? — could not be answered in the live app: the WhatsApp adapter card was badged dry-run while all 36 of its rows read MODE: live, and 64 simulated rows carried a green STATUS: ok under the heading “What the customer received”. Three changes fix it. One: mode and status are no longer two columns to cross-reference — they collapse into a single verdict, Reached them / Nobody got this / Failed, with the raw live / dry-run / ok values underneath it as the evidence. Two: an adapter’s mode and its rows read from the same field, so the card and the table cannot disagree; WhatsApp is Live because its deliveries are. Three: the count in the page head is the count that reached someone, not the row count.

36bDelivery failed /deliveriesA1 · error state · no reference exists

No failure has ever rendered in this product. All 100 deliveries are ok, all 12 workflow runs are Waiting or Completed, and 100% of knowledge documents are indexed — so the entire error vocabulary is invented here and needs the client’s confirmation. Three rules hold it together. A failure says what the guest did not get, not what the API returned. It names who is blocked and for how long, because a failed nudge on a live opportunity is a lost booking, not a log line. And it offers the one thing that would fix it — here the obvious fallback, SMS, is itself in test mode, so the drawer says so instead of offering a button that would do nothing. The drawer is also the narrower of the two widths: the verdict column it is opened from stays visible behind it.
